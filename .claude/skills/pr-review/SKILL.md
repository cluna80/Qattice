# PR Review

A good PR review for Qattice checks three things: correctness, architecture alignment, and hygiene.
Work through all three before posting any comments.

## Step 1: Get the diff

Use the GitHub MCP tools to fetch the PR:
- `pull_request_read` to get the PR description, branch, and metadata
- Review the file list — note which crates are touched

## Step 2: Architecture alignment (highest priority)

For every file changed, ask:

**Crypto / keys:**
- Does anything touch signature schemes? Is ML-DSA-65 still the only devnet consensus key type?
- Is Ed25519 being re-introduced anywhere? (Must not happen on devnet)
- Does `signature_scheme` stay `"pqc-native"` for ML-DSA chain user accounts?

**Consensus:**
- Does anything modify the Tendermint engine on devnet? (Should not)
- Is PQ-HotStuff work correctly isolated as a new module, not modifying the legacy `HotStuffEngine`?

**Genesis:**
- Is `genesis-4node-mldsa.json` still the supported devnet genesis?
- Are Ed25519 genesis files only touched as classical-compatibility test fixtures?

If any of these are violated, that's a blocking comment, not a nit.

## Step 3: Correctness

- Does the code do what the PR description says?
- Are there obvious logic errors, off-by-one issues, or missing error handling at system boundaries?
- Are new public APIs sensibly designed (types, error handling, naming)?
- Do tests actually test the new behaviour, or just compile?

## Step 4: Hygiene

- Is the branch targeting the right base?
- Are there debug prints, commented-out code, or TODO comments that should be resolved?
- Is the commit history clean (no "fix fix fix" chains that should be squashed)?
- Does the commit message follow the project format?

## Step 5: Post comments

Use `pull_request_review_write` to create a pending review, then `add_comment_to_pending_review`
for inline comments, then submit. Structure comments as:

- **Blocking**: architecture violations, correctness bugs — must be fixed before merge
- **Suggestion**: improvements that would be nice but aren't blockers
- **Nit**: minor style issues — prefix with "nit:"

End every review comment with:
```
---
_Generated by [Claude Code](https://claude.ai/code)_
```

## Step 6: Summary

After posting, give the user a one-paragraph summary: what the PR does, any blocking issues,
and your overall recommendation (approve / request changes / needs more info).
