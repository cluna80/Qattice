# PQ-HotStuff-2 recovery stack (#143, #144, #145) — focused review

**Status: DRAFT; documentation of a review, not an approval.** Scope: checkpoint authentication, the SafetyStore signing floors, the staging and restart boundaries, and the two process-level mutants that survived. Profile v3 stays off by default, network snapshot installation stays disabled, pruning is not implemented, dynamic membership is disabled (PO-4), payloads are devnet-interim (U5), Tendermint is unchanged, production keys and counter stay gated (#109). The recovery exercised is **operator-staged recovery of the devnet-interim application** - not Qattice application recovery and not automated network installation.

**Method.** Read the code paths against the stated invariants; for every suspected gap, write a test that FAILS on the current code first, then fix, then mutate the fix to show the test notices; keep what was examined and left unchanged on the record.

### The controlled-leader scenario, and what it showed
`live_v3_a_recovering_node_that_leads_its_round_is_asked_to_propose_refuses_and_signs_nothing`: the victim is wiped and re-staged (the staging tool's `--lag K` ends the evidence K blocks before the donor's tip, with an older valid QC) and started until its first status says it is the leader of its post-install round and still recovering; the test then waits for the node to report that its engine was **asked to propose and refused** (recorded run: 10 refusals), and checks that nothing was signed or sent and that the node still recovers and agrees. **Structural fact it uncovered:** while the victim is down, no QC can form for the round just before its own leader slot (it would have to aggregate those votes), so the donors' *recent* chains never contain the one QC round that puts it on its slot; staging from the donors' tips never made it the leader (24 attempts). The evidence must reach back across the moment the victim went down.

## Examined and left unchanged
**Checkpoint authentication.**
* `seed::authenticate_checkpoint` is the only constructor of a seed. It requires: a header chain from genesis that passes the same header verifier the engine's rules use (proposer signature by the round's leader, QC for every parent, TC, reference rules R1-R4 and R6); the checkpoint block final under the two-chain predicate; a **final** header carrying the identical (height, block id, state root) - that carrier is what attests the root; a valid high QC certifying a verified header at or above the checkpoint. An install record is never evidence (`check_install_record` is a cross-check against an already-authenticated seed).
* Persisted evidence is re-authenticated at **every** start by `Engine::authenticate_evidence` against the node's OWN genesis hash (which binds the checkpoint parameters), profile, chain id, validator set and leader seed - never against values carried in the evidence. Damaged evidence, evidence that does not describe the checkpoint its record claims, and unauthentic evidence each stop the node before it signs.
* The staged application state is bound to the attested root twice: the staging tool refuses unless the replayed interim state digest equals the attested root, and `Driver::start` refuses unless the executor's cursor at the base height has the attested block id and state digest.
* **Limit (documented):** evidence starts at genesis, so re-authentication costs O(chain) signature verifications per start and grows without bound until anchored evidence exists.

**Signing floors.** The SafetyStore is never written by seeding or by `complete_recovery`; the whole record (floors, last vote, last timeout, last proposal, counter) is compared bit-for-bit across seed, dependency arrival and completion in-process. The engine's round is raised to at least `hvr` and never lowered. The three signing sites (`vote_for`, `propose_with`, `local_timeout`) and both stored-message re-sends are gated; each gate is mutation-caught deterministically in-process and, except the stored-timeout re-send, at the process level. Recovery completes only when the high QC's block is known and the high QC round is not below the store's `hqr`. The runtime monitor in the node stops it if the signing counter moves, or if it sends a vote, timeout or proposal it authored, while recovering.

**Staging and restart boundaries.** Order of the staging writes: staleness and executor checks (read-only), evidence (replaces a record for the same checkpoint atomically; a different block at the same height is a conflict), application state (temporary file, sync, rename, sync the directory). A crash after the evidence leaves new evidence over an older executor: the node **refuses to start** (`below the seeded checkpoint`), writes no status, and the signing-safety files and counter value/digest are unchanged; a crash after the rename leaves a consistent generation. On restart the base is rebuilt from the re-authenticated evidence, the newest evidence is the base, commit markers at or below it are not required and the rest must continue without a gap, a damaged newest record is an error (no fallback to an older one), and an executor behind or different at the base stops the node.

## Residual risks and limits
* Crash model is **process death** (SIGKILL/TerminateProcess and an injected exit between staging writes). Power loss and fsync reordering are not tested.
* The staging tool reads the donor's files while the donor runs and retries on a half-written chain; taking the target's data-directory lock creates the directory and the empty `LOCK` file if they are absent, so "the entire target is unchanged" holds for a target that has run before.
* The storage and wire surfaces are devnet-only: the test-only crash hook (`PQDEV_TEST_STAGE_CRASH`) exists in the devnet binary, and `--lag` is a test aid.
* The execution log can lose one line if a process dies between the durable application step and the append (never repeat one).
* Not addressed here: automated network installation, bounded/anchored evidence, a real application snapshot and state root, pruning, a power-loss crash model, and Windows evidence for the changes made in this review.
